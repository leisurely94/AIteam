# 可直接试跑的目标

把下面任意一条直接丢给 `python3 -m ai_team run "..."` 或 `chat`，观察团队构成和产物差异。

## 产品/工程类

1. `为质量团队做一个周报自动汇总工具：拉取任务与缺陷数据，生成周报并支持导出`
2. `设计一个接口自动化回归平台：支持用例编排、定时执行与失败归因`
3. `把现有的测试环境申请流程做成自助页面：查询档期、提交申请、自动通知`
4. `为数据平台做一个指标口径字典，覆盖核心看板并支持影响面查询`

## 质量/流程类

5. `梳理上线前的质量门禁清单，并给出可执行的检查脚本与责任人`
6. `设计一套线上问题复盘模板与归档流程，支持按影响面分级`

## 文档/内容类

7. `写一份新同学上手手册，覆盖环境搭建、调试、提测和发版`
8. `为内部工具写一份使用指南，包含常见问题与故障排查`

## 观察点

| 目标 | 预期团队差异 |
| --- | --- |
| 1 | 产品 / 架构 / 数据 / 测试 / 评审 |
| 2 | 产品 / 架构 / 后端 / 测试 / 评审 |
| 7 | 产品 / 架构 / 测试 / 文档 / 评审 |
| 8 | 产品 / 架构 / 文档 / 评审 |

瓶颈排查建议：

- 团队角色不对 → 目标里写清技术方向（前端/后端/数据/文档），规则实现按关键词选角
- 产物太泛 → 用 `--interactive` 补充约束与验收口径，基线会带着这些信息进入每个角色
- 评审总是通过 → 接真实模型，评审提示词会强制逐条对照验收标准
